多模态 Token 编码
通俗解读让原本只会读文字的 Transformer 学会"看图、听声音"：把图片切成小块、音频切成片段，各自转成模型能读的数字编码，再和文字混在一起喂给模型，从此文字、图像、视频共用一个大脑。
突破与成果打破了大模型"只能吃文字"的限制，催生了 GPT-4V、Gemini、Claude、Qwen-VL、Kimi-VL 等一批能识图、看视频的多模态模型，也让"图生文、文生图、音视频理解"成为今天 AI 产品的标配能力。
专业词汇解释
视觉编码器 — 把整张图像压缩成一组特征向量的神经网络，相当于模型的"眼睛"前段
投影层 — 把视觉特征的维度对齐到文字向量空间的线性变换，让两种模态能"对话"
Token — 模型处理信息的基本单元，文字按词/子词切分，图像按块切分

Input & Embedding · 多模态输入在此接入
为什么需要这个模块：Transformer 无法直接处理文字，必须先把离散 token（词/子词）映射为稠密向量，作为全模型统一的数值输入。它决定了"信息以什么形式进入网络"。创新方向：多模态信号接入（视觉/音频编码）、共享嵌入省参数。
2022–25
多模态 Token 编码GPT-4V / Gemini / Qwen-VL / Kimi-VL / Claude
为什么需要：原生 Transformer 只吃文本，图像 / 视频 / 音频进不来；要让模型"看图、听懂"，必须把非文本信号接入同一个输入通道。
创新与优势：在输入嵌入前加视觉 / 音频编码器 + 投影层，把多模态信号压成与文本对齐的 token 序列，一次训练同时吸收多模态信息，产品上实现识图、视频理解。
OpenAIGoogleAlibaba QwenMoonshotAnthropic
Positional Encoding · 解决注意力"无序"问题
为什么需要这个模块：注意力对输入"一视同仁"，交换任意两个 token 的位置它都看不出区别；语言却高度依赖词序。位置编码就是给每个 token 注入"位置标签"，让模型知道先后关系。创新方向：让位置表达更合理（相对位置）、支持上下文外推与超长序列。
2021
RoPE 旋转位置编码RoFormer 2021（DeepSeek / Qwen / Kimi / Grok-1 采用）
为什么需要：原版绝对正弦位置编码只记"第几位"，难以表达相对关系，且外推到更长序列效果差。
创新与优势：把位置信息编码成 Q/K 向量的旋转角度，点积后自动携带相对位置；无需学习参数、外推性好，成为 DeepSeek / Qwen / Kimi / Grok-1 等的主流选择。
经典论文
2021
ALiBi 线性偏置Press et al. 2021
为什么需要：加位置向量会干扰注意力分数，且训练长度与推理长度不一致时表现崩坏。
创新与优势：干脆不注入位置向量，按 token 距离给注意力分数加线性惩罚；实现"训练短文本、推理长文本"，外推简单高效。
经典论文
2023
位置插值 / YaRNChen et al. 2023 / Peng et al. 2023（DeepSeek-V3 128K 采用）
为什么需要：RoPE 直接外推有上限，想从 4K 上下文拉到 128K 会失效甚至崩溃。
创新与优势：对 RoPE 频率做插值 / NTK 缩放，无需重新训练即可扩展上下文（DeepSeek-V3 用其支撑 128K），且保留短上下文性能。
经典论文
Self-Attention · 含编码器自注意力与解码器掩码自注意力
为什么需要这个模块：它是 Transformer 的"核心引擎"：让每个 token 与序列中所有 token 两两交互，按相关性加权聚合信息，解决"谁和谁相关"的长距离依赖问题（取代 RNN 的串行递归）。代价是 O(n²) 计算与 KV 缓存开销。创新方向：省缓存（GQA/MQA/MLA）、省计算（FlashAttention/滑动窗口）、超长序列并行（Ring Attention）。
2019
MQA 多查询注意力Shazeer 2019（PaLM 等采用）
为什么需要：在 GQA 之前，先想如何把多头注意力的缓存开销压到最低。
创新与优势：所有 Q 头共享同一组 K/V，缓存降为 MHA 的 1/头数、解码最快；代价是少量质量损失，大模型早期常用。
Google
2022
FlashAttentionDao et al. 2022 / FlashAttention-2 2023（所有主流模型）
为什么需要：标准注意力要把 N×N 矩阵写入显存，长序列直接显存爆炸，训练又慢。
创新与优势：IO 感知的分块计算 + 在线 Softmax，不物化完整矩阵；省显存、快数倍，成为高效训练与长上下文的地基。
经典论文
2022
GQA 分组查询注意力Google 2022（LLaMA-2 / Qwen2 / Gemma / Qwen3 采用）
为什么需要：MHA 每个头独享一份 K/V，KV 缓存巨大，推理内存带宽成为瓶颈。
创新与优势：把 Q 头分组、每组共享一份 K/V（Qwen3-235B：64 个 Q 头 / 4 个 KV 头），缓存与带宽显著下降，质量接近 MHA，成为事实标准。
Google
2023
Ring AttentionLiu et al. 2023
为什么需要：单机显存放不下超长序列的注意力中间结果，长上下文训练做不动。
创新与优势：把序列分块在多设备间环形传递并行计算，让百万级 token 上下文训练成为可能（Gemini 1.5 类长上下文的关键技术）。
经典论文
2023
滑动窗口注意力 SWAMistral 2023（Qwen3-Next 混合注意力）
为什么需要：全量注意力是 O(n²)，序列一长计算和显存都撑不住。
创新与优势：每 token 只看窗口内邻居，计算降到 O(n)；与全局注意力交替成"混合注意力"，兼顾局部细节与全局信息。
经典论文
2024
MLA 多头潜在注意力DeepSeek-V2 2024（DeepSeek-V3 / Kimi K2 采用）
为什么需要：GQA 仍要缓存完整 K/V，长上下文推理的显存与成本依然高企。
创新与优势：把 K/V 低秩压缩成"潜在向量"再上投影恢复，KV 缓存降低约 90%；DeepSeek-V3 与 Kimi K2 采用，长上下文性价比标杆。
DeepSeek
Cross-Attention · 解码器读取编码器输出（Q 来自解码器，K/V 来自编码器）
为什么需要这个模块：它是解码器与编码器之间的"桥梁"：Q 来自已生成部分，K/V 来自编码器输出，把源信息的语义按需注入生成过程（翻译、摘要、多模态对齐的核心）。创新方向：门控注入控制"多少信息进来"、潜在数组压缩输入以控制成本。
2021
Perceiver 潜在数组DeepMind 2021
为什么需要：图像 / 音频输入动辄几十万 token，交叉注意力成本随输入长度爆炸。
创新与优势：用固定大小的"潜在数组"压缩输入再做交叉注意力，计算量与输入长度解耦，适合多模态长输入。
Google
2022
门控交叉注意力Flamingo（DeepMind）2022
为什么需要：把视觉 token 全量塞进文本主干，计算爆炸且训练不稳定。
创新与优势：视觉特征经"门控"按需注入文本主干，模型可学习每次注入多少；数据效率高，成为多模态主流范式（Gemini / GPT-4V 思路）。
Google
Feed-Forward & MoE · 参数扩大但计算不变的稀疏化方向
为什么需要这个模块：注意力本质是线性加权，表达能力有限；FFN 对每个位置独立做非线性变换，负责"存储与回忆知识"。它是模型中参数量最大的部分。创新方向：激活函数升级（SwiGLU）、专家化稀疏（MoE：参数变大而每 token 计算不涨）。
2020
SwiGLU 门控激活Shazeer 2020（LLaMA / Qwen / DeepSeek / Kimi 采用）
为什么需要：ReLU / GeLU 让 FFN 的表达力受限，同样参数量下质量上不去。
创新与优势：引入可学习门控（GLU 变体）提升表达与训练效率；如今几乎是所有新模型 FFN 的默认激活。
经典论文
2021
MoE 稀疏专家Switch Transformer 2021（MoE 范式）
为什么需要：模型越大越强，但每个 token 全参数计算，训练与推理成本线性爆炸。
创新与优势：把 FFN 拆成多个"专家"、路由只激活少量专家，参数量大幅增加而每 token 算力几乎不变；Gemini 1.5 等均沿用。
Google
2024
Gemini 1.5 稀疏 MoEGoogle 2024
为什么需要：长上下文 + 多模态需要极高能效的架构来支撑。
创新与优势：稀疏 MoE Transformer 支撑 100 万 token 上下文与多模态；官方技术报告对内部细节披露有限，但确立了"稀疏 + 超长上下文"的产品方向。
Google
2024
Grok-1 八专家 MoExAI 2024 开源权重
为什么需要：验证超大 MoE 的可行性，并给开源社区一个工业级研究对象。
创新与优势：314B 参数、64 层、8 个专家每 token 激活 2 个、上下文 8K；全量开源权重，是早期超大 MoE 的工程样板。
xAI
2024
DeepSeekMoEDeepSeek-V2 2024（V3 沿用）
为什么需要：朴素 MoE 路由容易"偏科"、负载不均，训练不稳定且推理并行效率低。
创新与优势：细粒度专家 + 共享专家 + 无辅助损失负载均衡（V3），路由更均衡、训练更稳；V3 为 671B 总参 / 37B 激活。
DeepSeek
2025
Qwen3 MoEAlibaba 2025
为什么需要：要同时兼顾性能与部署成本，并让开源模型具备思考能力。
创新与优势：235B 总参 / 22B 激活，128 专家每 token 激活 8 个，细粒度切分；配合思考 / 非思考双模式，开源推理模型代表。
Alibaba Qwen
Residual & Normalization · 深层网络训练的稳定性来源
为什么需要这个模块：模型要堆几十层才有能力，但层数越深，梯度越容易爆炸/消失、训练越不稳定。残差连接让梯度能直接回传，归一化稳定每层输出尺度，是"深得下去"的前提。创新方向：前置归一化（Pre-Norm）更稳、RMSNorm 更省计算。
2019
Pre-Norm 前置归一化GPT-2 2019
为什么需要：原版 Post-Norm（归一化在残差之后）在深层堆叠时梯度不稳、难以训练。
创新与优势：把 LayerNorm 移到残差支路之前，深层训练更稳定；几乎所有现代模型（GPT / LLaMA / Qwen / DeepSeek）沿用此布局。
OpenAI
2019
RMSNormZhang & Sennrich 2019（LLaMA / Qwen / DeepSeek 采用）
为什么需要：LayerNorm 要算均值与方差，工程开销偏大。
创新与优势：去掉均值中心化、只按均方根缩放，计算更省而训练同样稳定；LLaMA / Qwen / DeepSeek 的标配归一化。
经典论文
2026
Attention Residuals 注意力残差Kimi Team · Moonshot AI 2026-03（arXiv:2603.15031）
为什么需要：PreNorm 残差连接把所有层输出按固定单位权重相加，深度增加后隐藏状态不受控增长、每层贡献被逐渐稀释（PreNorm dilution），深层网络难以有效利用更早层的信息。
创新与优势：把固定相加换成对前序层输出的 softmax 注意力，每层按输入动态选择要聚合的历史层信息；Block AttnRes 分块跨块注意力 + cache 流水线通信把内存开销降到近零，可直接替换现有残差连接；scaling law 证明各规模一致提升，集成 Kimi Linear（48B 总参/3B 激活）预训练 1.4T tokens 后输出幅度与梯度分布更均匀、下游任务全面改善。
Moonshot · Kimi
Output Head · Linear + Softmax → 下一个词的概率
为什么需要这个模块：模型的隐藏状态维度与词表维度不同，输出头把隐藏状态映射到词表空间，再经 Softmax 变成"下一个词的概率分布"——每一次自回归解码都靠它出结果。创新方向：多 token 预测让训练信号更密、共享词表嵌入省参数。
2020
共享词表嵌入T5 2020（ALBERT 等）
为什么需要：输入与输出各维护一套大词表嵌入，参数量浪费。
创新与优势：输入输出共享同一套词表嵌入并做缩放，参数量大幅下降且性能不损失。
经典论文
2024
多 Token 预测 MTPDeepSeek-V3 2024 / Meta（Gloeckle et al.）2024
为什么需要：只预测下一个 token，训练信号稀疏、数据利用效率低。
创新与优势：同时预测后续多个 token，训练信号更密、效率更高；推理时可与投机解码配合加速（小模型草稿 + 大模型验证）。
DeepSeek
Training & Alignment · 不改变模块结构，改变"怎么训"
为什么需要这个模块：同样的架构，训练方法不同结果天差地别：预训练只让模型学会"续写"，不懂指令、不够安全。训练与对齐决定模型是否"有用、可控、会推理"，是 ChatGPT 与推理模型能力的来源。创新方向：从人工 RLHF 到 RLAIF、DPO，再到 GRPO 与可验证奖励驱动的推理涌现。
2022

Inference & Long Context · 服务侧与上下文工程
为什么需要这个模块：模型训完还要"跑得动、跑得快、装得下"：自回归一次一个 token 很慢，KV 缓存占显存，上下文太短装不下长文档。推理与上下文工程决定产品体验与成本。创新方向：KV 缓存管理（PagedAttention/Mooncake）、投机解码加速、百万级上下文。
2022
投机解码Leviathan et al. 2022（Medusa / EAGLE 等）
为什么需要：自回归一次只生成一个 token，解码慢、GPU 利用率低。
创新与优势：小模型快速"草稿"候选 token，大模型并行验证并一次接受多个，解码速度提升 2–3 倍。

2024
Mooncake 分离式推理Moonshot · Kimi 2024
为什么需要：长上下文推理中 K/V 缓存是最大成本，且大量请求高度重复、算力浪费。
创新与优势：以 K/V 缓存为中心的分离式架构：缓存复用 + 全局调度 + 预填充 / 解码分离，大幅压低 1M 级上下文的推理成本。
